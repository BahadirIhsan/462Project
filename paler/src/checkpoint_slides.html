② Sample preprocessing output: one entry → one 31-D vector

From key-down / key-up events: H = up − down of the same key, DD = down(next) − down(this), UD = down(next) − up(this) = DD − H. Shift+R counts as one keystroke (R), Enter is the 11th key. The vector is stored in key order: H.period, DD.period.t, UD.period.t, H.t, … , H.Return.

③ Observed quality issues

  • Key overlap: 10.8% of UD values are negative (54% of entries have ≥1); per subject 0%–35%. Real typing behaviour, kept.
  • Long pauses: 189 entries contain a latency > 2 s; longest entry 36.0 s (s049, S1, one pause of 26.0 s).
  • Practice effect / drift: median entry time falls 2.80 → 2.08 s; within-session variation is also large (mean CV 0.18).
  • Redundant features: DD = H + UD exactly, so a user's 31×31 covariance has rank 21 → Mahalanobis needs a ridge term.
  • Lab conditions: one laptop + external keyboard, 50 entries in a row; browser timing in our demo will differ, so demo accuracy is not evidence.
  • Ground truth limits: subject IDs have gaps (5 absent IDs, as released); typo behaviour is not recorded.

④ Samples rejected during preprocessing

Rule (enrolment entries only): reject an entry whose total time exceeds k × the user's own median over that user's enrolment entries. Chosen value k = 2; computed without any test data.
