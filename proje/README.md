# BİL462 Project A5 – Keystroke Dynamics: Password-Typing Verification Across Sessions

Bahadır İhsan Herdem (221101034), Ömer Efe Öztürk (221101059)

Distance detectors (Manhattan, scaled Manhattan, Mahalanobis), a per-user one-class SVM and a shared Siamese
embedding are evaluated on the CMU Keystroke Dynamics Benchmark within a session (C1) and across sessions (C2),
plus a template-ageing curve, score fusion, a replication of Killourhy & Maxion (2009) and an error analysis.
A localhost demo (`demo/`) uses the same code as a password + typing-rhythm login.

## 1. Setup

Python 3.12+ (tested with 3.14.3 on macOS, CPU only).

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Data (not included)

The dataset is not redistributed. Download `DSL-StrongPasswordData.csv` from the CMU benchmark page
<https://www.cs.cmu.edu/~keystroke/> (Killourhy & Maxion, DSN 2009) and either

* put it at `data/DSL-StrongPasswordData.csv`, or
* set `KEYSTROKE_CSV=/path/to/DSL-StrongPasswordData.csv`.

The page asks users of the data to inform the authors of publications and to state when the methodology differs
from the original paper (our C1/C2/ageing/fold protocols differ; C3 replicates it).

No model weights need to be downloaded: the Siamese network is small and is trained by the scripts
(`results/siamese_demo.json`, ~1 MB, is regenerated by `final_experiments.py`).

All runs use fixed seeds (subject split seed 0, bootstrap seed 0, torch seed 0); re-running gives identical JSON.

## 4. Code layout

```
keystroke/data.py         load CSV → array [subject][session][rep][31]; tuning/evaluation subject split
keystroke/preprocess.py   validation checks, enrolment-only rejection rule
keystroke/detectors.py    Manhattan, ScaledManhattan, Mahalanobis, OCSVM (fit on genuine enrolment entries only)
keystroke/siamese.py      shared MLP embedding, batch-hard triplet loss, per-user centroid detector
keystroke/experiments.py  protocols C1, C2, ageing, C3; SVM tuning; multi-entry fusion; operating points
keystroke/metrics.py      FMR/FNMR sweep, EER, DET on a fixed grid, subject bootstrap CI
demo/                     Flask + SQLite demo (see below)
tests/test_demo.py        replays CMU rows as browser key events through the demo API
```

Evaluation rules followed: hyper-parameters chosen only on the 10 tuning subjects; results on the other 41;
enrolment and test entries always different and test entries always later; the shared Siamese model is
cross-fitted so that neither evaluated users nor their test impostors were seen in training; operating-point
thresholds use enrolment data only; CIs resample subjects.

## 5. Demo (localhost)

```bash
python demo/app.py          # http://127.0.0.1:5000
python tests/test_demo.py   # automated end-to-end check (no browser needed)
```

1. **Register**: username + password (6–32 characters). Choosing the CMU password `.tie5Roanl` additionally enables
   the Siamese detector (trained on the 51 CMU subjects).
2. **Enrol**: type the password + Enter at least 15 times (30+ recommended). Use "Start new session" later
   (e.g. the next day): with ≥ 2 sessions the threshold is learned leave-one-session-out.
3. **Log in**: password hash check, then rhythm check (scaled Manhattan + one-class SVM [+ Siamese], z-normalised
   with the user's held-out enrolment scores, threshold = 90/95/99th percentile by security level). Optionally
   average 3 entries.
4. **Impostor test**: another person types your password in "impostor test" mode; logged, never signs in.
5. **My data**: security level, attempt history, delete account and all biometric data.

Interface language: Turkish by default; switch with **TUR / ENG** in the header (stored in a `lang` cookie). The language
changes only the displayed text: enrolment, scores, thresholds and decisions run through the same code and are identical in
both languages (checked in `tests/test_demo.py`). All UI strings are in `demo/i18n.py`.

Storage (`demo/instance/keystroke_demo.db`, SQLite, created on first run; excluded from the ZIP):
`users` (username, scrypt password hash, consent time, level), `samples` (enrolment timing vectors only, no key text),
`attempts` (claimed user, role, z-scores, threshold, decision). Demo data are never used in the CMU evaluation.
